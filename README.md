# krolikov.net

**Krolikov** — веб-приложение для поиска и распознавания музыки по аудиофайлу, микрофону и тексту песни. Результаты дополняются текстами песен, обложками, короткими аудиопревью и рекомендациями.

## Возможности

- **Распознавание аудиофайла.** Сначала используется Chromaprint/AcoustID, а при неудаче — Yandex AI Studio Agent.
- **Распознавание с микрофона.** Запись браузера конвертируется на backend в MP3 и передаётся Yandex AI Studio Agent.
- **Поиск по тексту песни.** Короткие запросы сразу отправляются в LRCLIB; длинные фрагменты анализирует Yandex AI Agent, после чего результаты проверяются через LRCLIB.
- **Тексты песен.** Поиск и получение текста выполняются через LRCLIB; текст можно раскрыть в интерфейсе.
- **Похожие треки.** Yandex AI Agent предлагает композиции, а приложение ищет соответствующие результаты в LRCLIB. Функция доступна и для трека, распознанного по аудиофайлу.
- **Рекомендации по жанру.** Агент предлагает песни по заданному жанру, затем приложение ищет их в музыкальном каталоге.
- **AI-анализ трека.** Gemini формирует описание, жанры, настроение и рекомендации.
- **Обложки.** Поиск через MusicBrainz и Cover Art Archive.
- **Аудиопревью.** Если для трека найден фрагмент в iTunes Search API, на обложке появляется кнопка воспроизведения 30-секундного отрывка. Одновременно воспроизводится только один предпрослушиваемый трек.
- **Анимированный интерфейс.** Тёмная тема с вращающимися ambient-лучами; во время предпрослушивания цвета подсветки подбираются по обложке и сбрасываются при остановке.
- **История и ML-рекомендации.** Отдельный Python-сервис с FastAPI, scikit-learn и PostgreSQL хранит поисковые события и каталог текстов, а также рассчитывает текстовое сходство треков.

## Как устроен поиск по тексту

Запрос без переносов строк длиной до **8 слов и 120 символов** считается коротким поиском по исполнителю/названию и отправляется напрямую в LRCLIB.

Длинный текст или фрагмент песни передаётся Yandex AI Agent. Агент использует настроенный инструмент `web_search`, чтобы определить исполнителя и название. Затем приложение выполняет поиск через LRCLIB и дополняет найденные результаты обложками, если они доступны.

## Распознавание аудио

### Аудиофайл

1. Backend принимает файл размером не более **20 MB**.
2. Chromaprint (`fpcalc`) создаёт аудиофингерпринт.
3. AcoustID используется для поиска совпадений, а MusicBrainz — для метаданных записи.
4. Если классическое распознавание не даёт результата, приложение пробует распознать файл с помощью Yandex AI Studio Agent.
5. Найденный трек дополняется текстом и обложкой, если они доступны.

### Микрофон

Браузер записывает короткий аудиофрагмент. Backend конвертирует его через FFmpeg в MP3 и передаёт Yandex AI Studio Agent. При успешном распознавании приложение ищет обложку через MusicBrainz и Cover Art Archive.

## Предпрослушивание и обложки

Для найденных треков приложение запрашивает короткие фрагменты через iTunes Search API. Воспроизведение доступно только тогда, когда API вернул подходящий фрагмент; наличие обложки само по себе не гарантирует наличие превью.

Обложки ищутся по метаданным MusicBrainz, а изображения релизов загружаются из Cover Art Archive. Если обложку или аудиофрагмент найти не удалось, приложение продолжает показывать карточку без соответствующего элемента.

## AI-анализ и рекомендации

Gemini используется для анализа трека. Yandex AI Studio Agent отвечает за распознавание аудио с микрофона, обработку длинных текстовых запросов, поиск похожих треков и рекомендации по жанру. После рекомендаций приложение старается получить соответствующие музыкальные данные и тексты через LRCLIB.

Дополнительный ML-сервис выполняет **текстовое сопоставление**, а не обученную классификацию музыкальных жанров:
- **scikit-learn** — TF-IDF-векторизация текстов и cosine similarity для ранжирования похожих текстов;
- **FastAPI** — HTTP API сервиса аналитики;
- **PostgreSQL** — хранение каталога треков и поисковых событий;
- **SQLAlchemy** — работа с базой данных.

Для получения осмысленных результатов ML-поиска добавьте в каталог не менее двух треков с непустыми текстами.

## Основные API

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/api/recognize/file` | Распознавание аудиофайла через Chromaprint и AcoustID |
| POST | `/api/yandex/recognize` | Распознавание аудио через Yandex AI Studio Agent |
| GET | `/api/lyrics/search?q=...` | Поиск песни или текста через LRCLIB с обработкой длинных запросов |
| POST | `/api/gemini/analyze` | AI-анализ трека через Gemini |
| POST | `/api/yandex/generative` | Запрос к Yandex AI Agent |
| POST | `/api/music/previews` | Поиск доступных аудиопревью |
| POST | `/api/analytics/events` | Сохранение поискового события |
| GET | `/api/analytics/history` | Получение последних поисковых событий |
| POST | `/api/analytics/tracks` | Сохранение трека и его текста |
| POST | `/api/ml/similar` | Поиск похожих сохранённых текстов |

## Переменные окружения

Создайте локальный файл `.env` на основе примера:

```bash
cp .env.example .env
```

В Windows можно скопировать файл вручную и назвать копию `.env`.

Основные переменные:

```env
VITE_APP_NAME=Krolikov
VITE_THEME=dark
VITE_LRCLIB_API_URL=https://lrclib.net/api/

ACOUSTID_CLIENT_KEY=
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.6-flash

YANDEX_API_KEY=
YANDEX_AGENT_ID=fvtm93a73klntd04lf7p

POSTGRES_DB=krolikov
POSTGRES_USER=krolikov
POSTGRES_PASSWORD=change-me-for-production
```

Yandex AI Agent вызывается backend через OpenAI-compatible API:
- Base URL: `https://ai.api.cloud.yandex.net/v1`
- Agent ID задаётся через `YANDEX_AGENT_ID`.
- API-ключ задаётся через `YANDEX_API_KEY`.

**Не публикуйте реальные ключи, пароли или файл `.env` в GitHub.** Переменные `VITE_*` попадают во frontend bundle, поэтому секреты нельзя хранить в них.

## Локальный запуск

Требуется Node.js 22+ и доступ к необходимым API. Для распознавания файлов локально нужны Chromaprint/`fpcalc`; для конвертации аудио с микрофона нужен FFmpeg.

Установка зависимостей:

```bash
npm install
```

Запуск frontend в режиме разработки:

```bash
npm run dev
```

Запуск backend в отдельном терминале:

```bash
npm run server
```

Production-сборка frontend:

```bash
npm run build
```

Предварительный просмотр production-сборки:

```bash
npm run preview
```

## Запуск через Docker Compose

Compose запускает приложение, Python-сервис аналитики и PostgreSQL.

```bash
docker compose up -d --build
```

Приложение будет доступно по адресу:

```
http://localhost:3000
```

Просмотр логов:

```bash
docker compose logs -f krolikov
```

Остановка контейнеров:

```bash
docker compose down
```

Чтобы пересобрать только приложение после изменений frontend/backend:

```bash
docker compose up -d --build krolikov
```

Для production обязательно задайте надёжные значения `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`. Не используйте демонстрационные значения из примера в публичном окружении.

## Ограничения

- Точность распознавания зависит от качества записи и наличия совпадения в AcoustID/MusicBrainz либо от ответа AI-агента.
- Ответы AI могут содержать ошибки и не всегда точно определяют песню.
- LRCLIB может не содержать текст нужной композиции.
- Обложки и превью доступны не для всех треков.
- Поиск похожих текстов в ML-сервисе зависит от данных, сохранённых в каталоге.
- Внешние сервисы могут ограничивать частоту запросов или временно быть недоступны.
